# Climb: agent guide

Coaching-first Deadlock tracker for any Steam account. Build-less PWA: plain `<script>` files, no
bundler or npm, localStorage, data from deadlock-api.com only. Live at
https://tripod110.github.io/climb/ (GitHub Pages, served from `main`). README.md covers features
and the helper in depth; this file is the rules.

## Layout
- `js/engine.js`: every number the app shows. Pure functions, no DOM, exported on `window.Engine`.
- `js/views.js`: one render function per tab (overview, coach, matches, match, heroes, friends,
  friend, play, about). Builds HTML from Engine output; never computes a stat itself.
- `js/app.js`: state, loading, caching, hash routing (`#/overview`, `#/heroes/<id>`, …).
- `js/charts.js`: hand-rolled SVG/HTML charts. `js/api.js`: deadlock-api calls.
- `js/store.js`: localStorage, namespaced per account (`climb.<account>.<key>`).
- `js/changelog.js` + `CHANGELOG.md`: release notes (the app shows the first as "What's new").
- `js/wpmodel.js`: the trained win-chance model, generated by `model/train.py`; don't hand-edit.
- `helper/`: optional Windows helper (Python) that logs play sessions; see README.
- `sw.js`: service worker cache. `index.html`: script tags with `?v=N` cache-busters.

## Run and test
- Serve the folder statically: `python -m http.server 8765 --bind 127.0.0.1` (also in
  `.claude/launch.json`), open http://127.0.0.1:8765/.
- Tests: `node js/tests.js` and `node js/play-tests.js`. Both must pass before any commit.
- The service worker only registers over https (the live site), where it caches hard. Locally the
  browser cache can still serve old files: hard-reload (or clear caches) before trusting what you see.

## Rules
- **Every number comes from Engine, with a test** in `js/tests.js`. A view may format and
  colour a number, never derive one.
- **Every change bumps the version**: `?v=N` on every asset in `index.html` and `sw.js`, and
  `const CACHE = 'climb-vN'` in `sw.js`. Without it, users keep the old cached app.
- **Every version gets a changelog entry** in both `js/changelog.js` (user-facing, plain
  language) and `CHANGELOG.md` (what changed in code). Versions display as `0.N`.
- **Design**: near-black page (`#0c0c0d`), brass (`--brass*`) for structure only, green and red
  mean only good and bad. System fonts only: the CSP blocks web fonts. Numbers over sentences;
  explanations go behind the small "i" source badge (`src()` in views.js), not in body text. A new
  term or unit gets one line in `GLOSSARY` (views.js, shown on About). Nothing may assume a rank:
  use `Engine.rankStatus` / `roadTier` (calibrating, unranked and Eternus all have to read right).
  Every page must work at 375px wide with no horizontal scroll.
- **Off limits**: Windows notifications, in-game mods, overlays, reading or writing game memory
  or logs from the web app.
- Small samples: anything that ranks people or heroes must shrink toward an average (see
  `heroInsights`, `stackBoard`) and only call "ahead/behind" when it holds in both halves.

## Branches and deploying
- Work and commit on `testing`. `main` is the live site: pushing to it deploys.
- Run `git fsck --full` before committing (the main dev PC has had disk corruption).
- Deploy only when the owner says so: see `.claude/skills/deploy`.
- Commit messages: short subject `0.N: what changed`, a body saying why.
